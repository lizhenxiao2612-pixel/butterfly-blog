把整篇博客丢给 AI「一键生成」，读起来会像说明书。更稳的用法是：你定方向，它帮你铺路，你再把句子改回自己的口气。

![把便利贴提纲变成一篇能发布的文章](/img/illust-blog.png)

## 推荐流程

1. **你写 5 行意图**：读者是谁、他们卡在哪、读完能做什么。
2. **让 AI 出提纲**：只要标题和小节，不要正文。
3. **你改提纲**：删掉正确但无聊的节，补上你真正想讲的例子。
4. **按节生成**：一次只生成一节，避免全文口气漂走。
5. **你通读一遍**：删套话、补失败经历、把「众所周知」全部划掉。

给提纲用的提示：

```text
读者：刚搭好 Hexo 博客、想开始写技术笔记的人。
主题：如何用 AI 辅助写博客，而不是让 AI 代写。
请给出 5 个小节标题，每个标题下一句说明这一节解决什么问题。
不要写正文，不要鸡汤。
```

## 让它改，而不是重写

有初稿之后，指定修改维度，比「润色一下」有用得多：

```text
下面是我的草稿。请只做三件事：
1. 删重复句；
2. 把抽象形容词换成可以执行的步骤；
3. 保持我的口语，不要改成正式公文。
不要增加新观点。
```

## 配图和封面

Butterfly 文章可以在 front-matter 里写 `cover` 和 `top_img`。插图用相对站点根路径，例如：

```markdown
![说明文字](/img/illust-blog.png)
```

图是给扫读用的，不要在正文里再复述一遍画面。图说「提纲变成文章」，文字就讲步骤。

## 发布前 30 秒检查

- 第一段有没有直接回答「这篇文章解决什么」
- 有没有至少一处你自己踩过的坑
- 代码或提示词能不能复制就用
- 有没有「赋能」「打造闭环」这种空词

写完后本地预览：

```bash
pnpm exec hexo new "文章标题"
pnpm exec hexo server
```
